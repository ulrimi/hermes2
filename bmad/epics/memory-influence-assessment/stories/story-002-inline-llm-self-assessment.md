# Story: Inline LLM self-assessment in same turn

**Story ID**: memory-influence-assessment-002
**Epic**: memory-influence-assessment
**Priority**: Medium
**Estimated Effort**: Medium (~1–2h)
**Status**: ✅ Complete
**Created**: 2026-05-19
**Completed**: 2026-05-19

## User Story

**As a** memory-instrumentation analyst
**I want** `memory_influence_self_assessment` reports to carry a real model-generated
verdict on which entries influenced the response, generated by a small extra LLM call
right after the foreground response settles
**So that** I can correlate write classifications against real `output_inference`
utility (not just substring matches) and detect paraphrased / stylistic influence.

## Business Context

### Problem Statement

The substring heuristic in Story 001 cannot detect paraphrased or stylistic influence.
For high-fidelity dead-weight analysis we need an actual model verdict per turn —
"which of these entries shaped my response, and which were dead weight."

### Business Value

Real `output_inference` signal closes the feedback loop the instrumentation was built for.
Cost is bounded: one small extra call per user turn, ~$0.001 with Haiku, ~1s latency.
Cheaper and simpler than the auxiliary-agent path (Story 003); higher signal than Story 001.

## Acceptance Criteria

**AC1:** Real assessment runs after foreground response
- **Given** a user turn completes with a `final_response`
- **When** `_emit_influence_assessment()` runs
- **Then** a single auxiliary LLM call evaluates each entry against the response
- **And** results populate `entries_explicitly_cited`, `entries_likely_influenced`,
  and `entries_present_but_unused` with `method="output_inference"`

**AC2:** Overall utility derived from model verdict
- **Given** the assessment call returns
- **Then** `overall_memory_utility_this_turn` is one of `high`/`medium`/`low`/`none`
  per the model's aggregate verdict
- **And** `overall_confidence` is `medium` (model judging its own output is imperfect)
- **And** `assessment_method` is `output_inference`

**AC3:** Failure modes degrade safely
- **Given** the assessment call times out, errors, or capacity-exhausts
- **When** `_emit_influence_assessment()` handles the failure
- **Then** the report is still emitted with `overall_utility="unassessed"`,
  `confidence="low"`, `method="error_fallback"`, and `reasoning` naming the
  underlying error class
- **And** the foreground turn is unaffected

**AC4:** Disabled-by-default config flag
- **Given** the feature carries cost and latency
- **When** the agent starts
- **Then** inline LLM assessment is off unless `memory.instrumentation.inline_llm_assessment: true`
  is set in config
- **And** when off, behavior falls back to Story 001's heuristic derivation

**AC5:** Latency budget bounded
- **Given** the inline call
- **When** any single assessment runs
- **Then** a hard timeout (default 5s) caps wall time, falling through to AC3 on overrun

**AC6:** Empty memory short-circuit
- **Given** no memory entries exist for the turn
- **When** `_emit_influence_assessment()` runs
- **Then** no LLM call is made, and the report is emitted with `overall_utility="n_a_no_entries"`

## Implementation Guidance

### Files to Modify/Create

  helper that returns a deterministic prompt string. Keep prompt builder pure / unit-testable.
- `run_agent.py` — replace stub body of `_emit_influence_assessment()` with:
  1. Empty-memory short-circuit (AC6)
  2. Read `inline_llm_assessment` flag; if off, run Story-001 heuristic and return
  3. Build prompt, issue auxiliary call with timeout, parse JSON response

  5. On failure / timeout: emit error-fallback report (AC3)

### Prompt Sketch

```
You just produced a response. For each memory entry below, classify its influence on the
response: cited (exact phrase from entry appears), likely_influenced (response references
the fact without quoting), or unused (response shows no sign of using this entry).

Memory entries:
1. [entry text]
2. [entry text]
...

Response:
[final_response]

Output JSON only: {"entries":[{"index":1,"verdict":"cited|likely_influenced|unused",
"reasoning":"one short sentence"}], "overall":"high|medium|low|none"}
```

def test_inline_assessment_populates_output_inference(mock_aux_llm, agent_with_memory):
    mock_aux_llm.return_value = (
        '{"entries":[{"index":1,"verdict":"cited","reasoning":"phrase appeared"}],'
        '"overall":"medium"}'
    )
    agent_with_memory._memory_store.memory_entries = ["use pytest-xdist"]

### Dev Agent Notes

**Files changed:**
- `agent/influence_assessment.py` (new) — shared module for stories 002 + 003.
  Contains pure helpers `build_influence_assessment_prompt()` (deterministic prompt
  builder with hard-cap truncation) and `parse_influence_assessment_response()`
  (robust JSON parser that handles code fences, surrounding prose, malformed JSON,
  out-of-range indices, unknown verdicts, and omitted entries). Also exposes
  `assess_influence_inline()` for the inline path and
  `spawn_influence_assessment_thread()` for the background path (Story 003).
- `agent/agent_init.py:954-994` — added config reads for `inline_llm_assessment`,
  `background_influence_assessment`, and `assessment_timeout_seconds`. All default to
  off / 5.0s. Initializes `_instr_precedence_logged` flag for one-shot AC7 logging.
- `run_agent.py:2062-2299` — refactored `_emit_influence_assessment` into a
  dispatcher that picks among three private helpers: heuristic (Story 001),
  inline (Story 002), background (Story 003). Precedence: background > inline >
  heuristic, with one-time INFO log when both LLM flags are on. Inline path uses
  `assess_influence_inline()` and emits `output_inference` (success) or
  `error_fallback` (any failure) reports.
- `tests/agent/test_influence_assessment.py` (new) — 23 tests: pure-helper tests
  (prompt determinism, truncation, parser variants) + 6 inline integration tests
  + 5 background integration tests + 1 stress test. All tests mock the aux client
  at `agent.auxiliary_client.get_text_auxiliary_client` so no real API calls.

**Choices worth noting:**

- Used `get_text_auxiliary_client()` directly rather than spawning a forked
  `AIAgent` (the background_review.py approach). For influence assessment the
  task is constrained — pass entries + response, get back JSON — so the full
  agent harness was overkill. Saves complexity and reduces failure modes.
- Hard-coded truncation limits (`MAX_ENTRY_CHARS=400`, `MAX_RESPONSE_CHARS=4000`)
  so a single oversized turn can't blow up token usage. These can be relaxed if
  assessment quality is insufficient.
- Confidence is `medium` (not `high`) on the output_inference path — the model
  judging its own output has known limits; honest tagging.
